# iPhone 知识库 PWA 设计方案

## 1. 背景

hyxClaw 在使用过程中会将知识库保存为 Markdown 文件，目录位于：

```text
$HYXCLAW_DATA_DIR/knowledge_base/
├── index.md
├── instructions.md
└── <知识库名称>/
    ├── index.md
    ├── <文章>.md
    └── <图片>.*
```

项目当前的知识库由文件系统直接持久化，没有数据库和向量数据库。全局 `index.md` 描述知识库列表，各知识库目录下的 `index.md` 描述该库的文章列表。这个结构天然适合被客户端下载后离线浏览。

本方案拟增加一个面向 iPhone 的只读 PWA（Progressive Web App，渐进式 Web 应用）：

- 用户可以将它添加到 iPhone 主屏幕，像普通 App 一样打开。
- 手机端只提供阅读和搜索，不提供编辑、删除或上传能力。
- 手机保存知识库的本地副本，支持离线阅读。
- 用户需要更新时手动点击“同步”，不做后台自动同步。
- 同步只涉及 `knowledge_base/`，不暴露会话、配置、日志和 API Key。

## 2. 目标与非目标

### 2.1 目标

第一版需要满足：

1. 在 iPhone Safari 中打开后可以添加到主屏幕。
2. 可以浏览全局知识库、知识库目录和 Markdown 文章。
3. 可以显示知识库中的本地图片，并支持 Markdown 相对链接。
4. 首次同步后可以在没有网络、没有运行 hyxClaw 的情况下阅读。
5. 用户点击同步后，客户端直接下载完整知识库快照。
6. 同步失败时保留旧版本，不破坏已有的离线数据。
7. 服务端严格限制为只读知识库内容。
8. 客户端和同步接口可以通过 Tailscale 等私有网络安全访问。

### 2.2 非目标

第一版不包含：

- 手机端编辑 Markdown。
- 手机端反向上传或删除文件。
- 手机端运行聊天、调用 LLM 或执行工具。
- Git 客户端功能。
- 后台定时同步和推送通知。
- 多用户权限管理。
- 在线全文搜索服务。
- 将整个 `$HYXCLAW_DATA_DIR` 暴露给手机。

## 3. 总体架构

```text
┌──────────────────────────────┐
│ Windows 上的 hyxClaw          │
│                              │
│ knowledge_base/              │
│  ├── Markdown                │
│  ├── 图片                     │
│  └── 两级 index.md            │
│                              │
│ /mobile PWA 静态资源          │
│ /api/mobile/* 只读同步接口    │
└──────────────┬───────────────┘
               │ 用户主动点击同步
               │ HTTPS / 私有网络
┌──────────────▼───────────────┐
│ iPhone PWA                   │
│                              │
│ Service Worker：缓存应用资源  │
│ IndexedDB：保存知识库快照     │
│ Markdown 渲染和全文搜索       │
└──────────────────────────────┘
```

PWA 由三部分组成：

- **应用壳**：HTML、CSS、JavaScript、图标和字体等静态资源，由 Service Worker 缓存。
- **知识库数据**：Markdown、图片和文件清单，存储在 IndexedDB 中。
- **同步协议**：PWA 通过专用只读 API 下载完整知识库快照。

应用壳缓存和知识库数据需要分开管理。更新 PWA 程序时不应删除用户已经同步的知识库；更新知识库时也不应强制重新下载应用壳。

## 4. 访问方式

### 4.1 开发和家庭局域网

开发阶段可以让 hyxClaw 监听局域网地址，例如 Windows 电脑的局域网 IP：

```text
http://192.168.x.x:3000/mobile
```

这适合调试普通页面和接口，但 iPhone 上的 PWA 离线能力依赖 Service Worker，而 Service Worker 通常要求安全上下文。除 `localhost` 等特殊情况外，远程 HTTP 地址不应作为正式方案。

### 4.2 推荐：Tailscale 私有网络

正式使用建议使用 Tailscale 连接 iPhone 和 Windows：

```text
iPhone ── Tailscale 私有网络 ── Windows hyxClaw
```

优势：

- 不需要将 hyxClaw 端口暴露到公网。
- 手机在家庭网络之外仍然可以手动同步。
- 可以使用 Tailscale HTTPS 或前置反向代理提供 HTTPS。
- 已经同步到手机的数据可以离线阅读，即使 Windows 电脑暂时关闭也不影响。

需要注意：Tailscale 只负责网络连通和网络层保护，不代替应用层认证。同步接口仍然需要独立的只读认证机制。

### 4.3 不建议直接公网暴露

不建议仅通过路由器端口转发，将 hyxClaw 的 HTTP 服务直接暴露到互联网。当前服务默认监听 `127.0.0.1`，这是安全默认值；如果为了手机访问而改成 `0.0.0.0`，必须同时配置 HTTPS、认证、访问控制和防火墙规则。

## 5. PWA 功能设计

### 5.1 页面入口

建议增加独立入口：

```text
/mobile
```

它与现有聊天页面分开，不复用聊天页面的会话、WebSocket、工具权限和编辑状态。

建议的页面结构：

```text
┌────────────────────────┐
│ 知识库           同步  │
├────────────────────────┤
│ 搜索知识库              │
├────────────────────────┤
│ 全部知识库              │
│  ├── 编程               │
│  ├── 人工智能           │
│  └── 读书笔记           │
├────────────────────────┤
│ 最近阅读                │
└────────────────────────┘
```

文章页面应提供：

- 文章标题和面包屑路径。
- Markdown 渲染。
- 目录导航。
- 图片显示。
- 相对链接跳转。
- 上一篇、下一篇或返回索引。
- 深色模式。
- 字号调整。
- “上次同步时间”。

### 5.2 只读约束

只读不仅是隐藏编辑按钮，还需要在协议和服务端同时保证：

- PWA 不实现 `PUT`、`POST` 文件内容和删除操作。
- 移动 API 只注册 `GET` 和必要的 `HEAD` 请求。
- 服务端路径解析只能落在 `knowledge_base/` 内。
- 即使用户手动构造请求，也不能访问 `config.json`、`conversations/`、`logs/` 或 `files/`。
- 返回内容不包含 API Key、会话历史和服务器绝对路径。
- 移动端不复用现有 `/api/documents/content` 的写入能力。

## 6. 同步协议

### 6.1 接口概览

建议增加独立的移动同步接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/mobile/snapshot` | 下载当前知识库完整快照 |
| `GET` | `/api/mobile/health` | 检查移动同步服务是否可用 |

第一版只需要实现 `snapshot`。用户每次点击同步都下载整库，客户端不判断是否有更新，也不实现逐文件同步。

### 6.2 完整快照同步

第一版直接返回 ZIP，不单独提供 manifest：

```http
GET /api/mobile/snapshot
Accept: application/zip
```

ZIP 内部直接保存相对于 `knowledge_base/` 的路径：

```text
index.md
instructions.md
人工智能/index.md
人工智能/attention.md
人工智能/attention.png
```

服务端生成快照时需要：

1. 扫描 `knowledge_base/`。
2. 只收集允许的文件类型和文件路径。
3. 拒绝符号链接逃逸到知识库目录之外。
4. 将当前目录内容打包成 ZIP。

客户端接收快照时需要：

1. 下载到临时存储。
2. 校验 ZIP 能够完整读取，且其中的路径均在知识库根目录内。
3. 解压到临时 IndexedDB 版本或临时目录。
4. 解压和导入成功后一次性切换当前数据。
5. 切换成功后再清理旧数据。

不能边下载边覆盖当前数据，否则网络中断可能导致用户看到半套知识库。

### 6.3 大型知识库

整库下载是自用场景下的首选。只要知识库规模在手机网络和存储空间可接受范围内，就不需要判断更新，也不需要维护增量同步逻辑。

同步按钮可以显示下载进度和本次下载大小；如果将来知识库大到整库下载不再合适，再单独设计增量同步。

## 7. 本地数据存储

### 7.1 IndexedDB

建议使用 IndexedDB，而不是把整套 Markdown 放进 `localStorage`：

- `localStorage` 容量小，不能可靠保存图片和大量文章。
- IndexedDB 适合按路径保存文本、图片和索引。
- 可以使用临时快照，避免同步失败破坏旧数据。
- 可以在客户端建立全文搜索索引。

建议的数据结构：

```text
database: hyxclaw-mobile

meta
  key: lastSyncedAt
  key: schemaVersion

files
  key: relativePath
  path
  kind
  content
  size

search
  key: relativePath
  normalizedText
  title
  headings
```

图片可以先保存为 `Blob`。如果第一版只使用 Data URL，简单但会增加内存占用；正式实现应优先使用 Blob URL 或直接从 IndexedDB 读取 Blob。

### 7.2 离线启动

离线打开 PWA 时：

- Service Worker 返回已缓存的应用资源。
- 客户端从 IndexedDB 读取当前快照。
- 同步按钮显示为不可用或提示“当前离线”。
- 用户仍然可以浏览、搜索和阅读已经同步的内容。
- 页面显示最后同步时间，而不是伪装成当前最新状态。

如果手机从未成功同步过，则显示空状态和同步指导，而不是显示应用加载错误。

## 8. Markdown 渲染

现有 Web UI 已经使用 Markdown 渲染模块。移动阅读器可以复用渲染规则，但不应直接复用聊天页面的状态和交互代码。

第一版支持：

- 标题、段落、列表和引用。
- 粗体、斜体、删除线。
- 表格。
- fenced code block 和代码高亮。
- 行内代码。
- Markdown 链接和图片。
- 数学公式（如果移动包体和离线资源允许）。

相对链接需要在客户端重写：

```text
当前文章：人工智能/attention.md
链接目标：../基础概念.md
解析结果：基础概念.md
```

链接目标必须再次经过本地路径校验，只允许打开当前知识库快照中的文件。不能直接将 Markdown 中的路径拼接为任意 URL 或任意本地文件访问。

外部链接可以使用系统浏览器打开，并应明确标记为外部链接。

Markdown 作为不可信输入处理：渲染时必须进行 HTML 转义或使用安全配置，禁止未经清理的原始 HTML 执行脚本。图片、链接和 HTML 标签都需要遵循内容安全策略。

## 9. 认证与安全

### 9.1 移动只读令牌

建议为移动同步增加独立令牌，不复用 LLM API Key，也不复用 GitHub Token：

```text
HYXCLAW_MOBILE_READ_TOKEN=<随机高强度令牌>
```

请求示例：

```http
Authorization: Bearer <mobile-read-token>
```

令牌权限仅限：

- 读取移动同步健康状态。
- 下载知识库 snapshot。

令牌不能调用聊天、工具、会话管理或现有文档写入接口。

### 9.2 配对流程

手工复制令牌可用于开发，但正式使用建议提供一次性配对：

1. Windows hyxClaw 的设置页生成一次性配对码或二维码。
2. iPhone PWA 扫描二维码。
3. 服务端验证短期有效的配对码。
4. 服务端只返回移动只读令牌。
5. PWA 将令牌保存在浏览器安全存储中。
6. 配对码立即失效，令牌可以在设置页撤销。

二维码中不应包含 API Key、完整数据目录路径或长期明文密码。二维码只应包含短期配对地址和一次性随机码。

### 9.3 服务端边界

移动接口必须固定以 `knowledge_base` 为根目录，不能由请求参数指定任意根目录。所有路径都需要：

- 统一使用 `/` 分隔符。
- 拒绝空路径、绝对路径和 `..`。
- 解析后验证路径仍在知识库根目录内。
- 拒绝符号链接指向根目录之外的文件。
- 限制单文件大小、总快照大小和文件数量。
- 对压缩包路径做 ZIP Slip 防护。

响应头建议包含：

```http
Cache-Control: private, no-cache
X-Content-Type-Options: nosniff
Content-Security-Policy: default-src 'self'; img-src 'self' data: blob:; frame-ancestors 'none'
```

实际 CSP 需要根据 Markdown 渲染、字体和数学公式资源调整，但不应允许任意远程脚本执行。

## 10. 与现有项目的关系

当前项目已经具备以下可复用基础：

- `src/config/paths.ts` 统一解析 `$HYXCLAW_DATA_DIR` 和 `knowledge_base` 路径。
- `src/server/services/knowledge.ts` 解析全局知识库索引。
- `src/server/services/documents.ts` 已实现知识库目录浏览和文件读取。
- `src/server/public/js/markdown.js` 已有 Markdown 渲染能力。
- 现有静态资源服务位于 `src/server/static-assets.ts`。
- 现有 HTTP 路由集中在 `src/server/routes/`。

但移动 PWA 不应直接复用以下能力：

- `/api/documents/content` 的 `PUT` 写入接口。
- 聊天页面的 WebSocket 和会话接口。
- 面向桌面布局的右侧文档编辑栏。
- 现有 Git 同步接口。

现有服务默认监听 `127.0.0.1`，只能在本机访问。要通过局域网或 Tailscale 访问，需要显式配置监听地址或使用反向代理。移动 PWA 的启用不应自动改变这个安全默认值。

现有 Git 同步功能只在回环地址上显示和启用。即使将服务改为远程访问，也不应因为移动 PWA 而放宽 Git 同步暴露条件；移动端同步应使用单独的只读 API。

## 11. 目录和静态资源建议

建议将移动 PWA 放在现有前端目录下的独立子目录：

```text
src/server/public/
├── mobile.html
├── mobile/
│   ├── app.js
│   ├── app.css
│   ├── manifest.webmanifest
│   ├── service-worker.js
│   └── icons/
│       ├── icon-192.png
│       └── icon-512.png
```

也可以使用 `src/server/public/mobile/` 作为入口目录，但需要保证：

- `/mobile` 能正确返回入口 HTML。
- `manifest.webmanifest` 的 MIME 类型正确。
- `service-worker.js` 的作用域覆盖 `/mobile`。
- Service Worker 的缓存名称包含应用版本。
- 静态资源路径不会与现有 `/js/`、`/styles/` 和 vendor 资源冲突。

如果移动页面和现有桌面页面共享 Markdown 渲染依赖，应评估离线缓存是否会把不必要的大型桌面资源一起下载。第一版可以先共享模块，后续再拆分移动包。

## 12. 同步交互

同步按钮建议有以下状态：

```text
未同步：      开始同步
同步中：      正在下载 42%
同步成功：    已更新 · 10:35
同步失败：    同步失败，仍使用旧版本
离线：        当前离线 · 可阅读旧版本
```

同步流程：

```text
点击同步
  │
  ├─ 检查网络和认证
  ├─ 下载完整 ZIP 到临时存储
  ├─ 校验 ZIP、文件路径和解压结果
  ├─ 写入新的本地快照
  ├─ 原子切换当前数据
  └─ 清理旧数据并刷新界面
```

异常处理：

- 认证失败：提示重新配对，不清理旧数据。
- 服务器不可达：提示检查 Tailscale、电脑状态和服务地址。
- 下载中断：删除临时下载，不影响当前快照。
- 校验失败：拒绝切换数据，并提示重新同步。
- 存储空间不足：保留旧版本，提示释放空间。
- 服务端知识库在生成快照期间发生变化：本次同步以打包完成的 ZIP 为准，下次同步再获取最新内容。

## 13. 快照和数据一致性

整库 ZIP 是客户端的最小一致性单位。客户端任何时候都只能展示一个完整的本地快照。

服务端生成 ZIP 时建议：

1. 扫描 `knowledge_base/` 内的文件。
2. 将文件复制到临时目录，或直接在一次打包操作中读取。
3. 从临时内容生成 ZIP。
4. 完成 ZIP 后再返回响应。

如果生成期间知识库被 AI 修改，自用场景下不需要加复杂的锁或重试机制；本次同步得到一个完整 ZIP 即可。用户下次点击同步时会重新下载当时的内容。

客户端至少保留当前快照，建议在替换期间暂时保留旧快照：

- 当前快照：用于正常阅读。
- 临时快照：导入成功后删除；失败时直接删除临时数据。

这样可以在不维护版本号的前提下，避免一次失败同步破坏旧数据。

## 14. 分阶段实现计划

### 阶段一：PWA 阅读器骨架

- 增加 `/mobile` 入口。
- 增加 `manifest.webmanifest`、图标和 Service Worker。
- 在手机上完成添加到主屏幕。
- 使用内置测试数据验证离线启动。

### 阶段二：只读移动接口

- 增加移动路由和知识库路径校验。
- 实现 ZIP snapshot 下载。
- 增加文件数量、单文件大小和总大小限制。
- 增加服务端测试，覆盖越权路径和空知识库。

### 阶段三：本地快照和手动同步

- 使用 IndexedDB 保存 Markdown、图片和同步时间。
- 实现临时下载、校验和原子切换。
- 实现离线阅读和搜索。
- 增加同步状态、错误提示和最后同步时间。

### 阶段四：认证和私有网络

- 增加移动只读令牌配置。
- 增加一次性二维码配对。
- 使用 Tailscale HTTPS 或反向代理提供安全访问。
- 增加令牌撤销和重新配对流程。

### 阶段五：体验优化

- 目录导航和文章目录。
- 阅读历史和最近阅读。
- 相对链接完善处理。
- 更好的图片压缩、下载进度和存储空间提示。

## 15. 验收标准

第一版完成后应满足：

- iPhone Safari 可以打开 `/mobile` 并添加到主屏幕。
- 首次同步可以完整下载一个包含 Markdown、子目录和图片的测试知识库。
- 关闭网络和 Windows 服务后，已同步文章仍然可以打开。
- 修改、新增或删除知识库文件后，点击同步可以获得完整的新内容。
- 重复点击同步会重新下载并完整替换，但不会损坏本地数据。
- 下载中断后，旧版本仍然完整可读。
- 手机端没有编辑、删除和上传入口。
- 未认证请求不能获取 snapshot。
- `../`、绝对路径、反斜杠绕过和符号链接不能越出 `knowledge_base/`。
- API Key、会话 JSONL、日志和其他数据目录文件不会出现在移动响应中。
- Markdown 中的脚本和危险 HTML 不会在 PWA 中执行。

## 16. 推荐决策

第一版采用以下组合：

```text
独立 PWA
+ /api/mobile/snapshot
+ ZIP 整库快照
+ IndexedDB 离线存储
+ 手动同步
+ Tailscale HTTPS
+ 独立移动只读令牌
```

暂不实现 manifest、版本判断、增量同步、原生 iOS App、后台同步和手机端编辑。这个组合改动范围最小，符合自用场景，也能在 Windows 环境完成开发和部署。

后续如果使用频率增加、知识库体积变大或需要系统级搜索，再考虑将 PWA 包装为 Capacitor App，或者开发独立的 SwiftUI 客户端；同步协议应尽量保持不变。
